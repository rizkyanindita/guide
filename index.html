⚠️ Step 1 — WAJIB SEBELUM APAPUN
🛑 Backup File Lokal Squad

Sebelum melakukan cherry-pick dari master, backup dua file berikut yang mungkin berbeda di setiap squad:

📄 run-maestro.sh

Script runner utama. Mungkin ada kustomisasi lokal yang perlu dipertahankan.

📄 .env

Konfigurasi environment squad. Berisi Device ID, CIF, App ID, dan credentials spesifik.

✅ Cara Backup Cepat

Copy kedua file ke lokasi aman sebelum lanjut ke step berikutnya:

bash — backup
# Copy file ke lokasi backup
$ cp run-maestro.sh run-maestro.backup.sh 📋 copy
$ cp .env .env.backup 📋 copy

❌ Jangan Skip Step Ini!

Setelah cherry-pick, file lokal akan tertimpa versi master. Tanpa backup, konfigurasi squad bisa hilang.

🔄 Step 3 — Alternatif: Cherry-pick by Commit ID
Cherry-pick dengan Commit ID

Gunakan cara ini jika ingin mengambil perubahan dari commit spesifik (bukan seluruh state master).

bash — git cherry-pick
# 1. Lihat daftar commit terbaru di master untuk cari Commit ID
$ git log --oneline origin/master -15 📋 copy
# 2. Cherry-pick commit spesifik ke branch kalian
# Ganti <commit-id> dengan hash dari step 1 (contoh: a3f9c12)
$ git cherry-pick <commit-id> 📋 copy
# 3. Jika ada conflict, resolve dulu lalu:
$ git add . && git cherry-pick --continue 📋 copy
# 4. Atau batalkan cherry-pick jika ada masalah
$ git cherry-pick --abort 📋 copy

🏷️ Step 6 — Running By Tags
Include Tags & Exclude Tags

Menjalankan test berdasarkan tag — dipakai lewat config squad maupun running by tag.

includeTags whitelist

Hanya menjalankan flow yang punya tag tersebut.

excludeTags blacklist

Menjalankan semua kecuali flow yang punya tag tersebut.

Logika OR — cukup salah satu tag cocok agar flow ikut terfilter. Contoh includeTags: [AT, coba] menjalankan flow yang punya tag AT atau coba.

1 Definisikan tag di TS Script
PNS-LGT-01-TC-01.yml
appId: ${APP_ID}
name: PNS-LGT-01-TC-01
jsEngine: graaljs
tags:
- AT
- coba
- Tech-imporve
2 Filter di config squad
squad-config.yml
flows:
- 'login/**'
-
includeTags:
- Regression
excludeTags:
- AT
executionOrder:
continueOnFailure: true
flowsOrder:
- TS_LOG_06

Device Commands
💻 Menyalakan & Mematikan Device

Device untuk test tidak ada di laptop Anda — semuanya ada di Mac Mini. Halaman ini memandu Anda dari nol: masuk ke Mac Mini, cek device yang aktif, menyalakannya, lalu mematikannya lagi.

1

🔐 Masuk dulu ke Mac Mini

Semua device ada di Mac Mini, bukan di laptop Anda — jadi Anda harus “masuk” ke Mac Mini dari jauh lewat SSH. Buka Terminal di laptop Anda, jalankan command di bawah, lalu ketik password saat diminta.

Terminal — laptop Anda
$ssh qa@10.54.134.99
# lalu ketik password ini — tulisannya memang tidak muncul saat diketik
$qa123
✅ Tanda berhasil: awal baris terminal berubah menjadi qa@…. Mulai dari sini, semua command di Langkah 2–4 dijalankan di jendela terminal yang sama.
2

🔍 Cek device mana yang sedang menyala

Selalu cek dulu sebelum menyalakan device baru — supaya tidak dobel dan tidak melebihi kapasitas Mac Mini. Dari langkah ini pula Anda mendapatkan nilai yang dibutuhkan di Langkah 3 & 4.

🍏 iOS — Simulator
# simulator yang sedang nyala — beserta UDID-nya
$xcrun simctl list devices booted
# semua simulator yang tersedia (nyala maupun mati)
$xcrun simctl list devices
🤖 Android — Emulator
# Device-id emulator berdasarkan squad name
for device in $(adb devices | grep "emulator" | awk '{print $1}'); do sleep 1 avd_name=$(adb -s $device shell getprop ro.boot.qemu.avd_name) echo "$device: $avd_name" done
# daftar semua AVD yang tersedia
$emulator -list-avds
📝 Catat hasilnya. Dari iOS Anda dapat UDID; dari Android Anda dapat AVD Name (mis. squad1) dan Emulator ID (mis. emulator-5554). Nilai-nilai inilah yang dipakai di Langkah 3 & 4.
3

🚀 Menyalakan device (booting)

Ganti bagian berwarna kuning dengan nilai asli dari Langkah 2 — tanda kurung sikunya ikut dihapus. Contoh: <AVD_NAME> → squad1.

🍏 iOS — pakai UDID
$xcrun simctl boot <UDID>
# contoh setelah diisi:
$xcrun simctl boot A1B2C3D4-5E6F-7A8B-9C0D-1E2F3A4B5C6D
🤖 Android — pakai AVD Name
$emulator -avd <AVD_NAME> &
# contoh setelah diisi:
$emulator -avd squad1 &
# kalau muncul "command not found", pakai path lengkapnya:
$~/Library/Android/sdk/emulator/emulator -avd <AVD_NAME> &
💡 Tanda & di akhir command Android berarti emulator berjalan di belakang layar, sehingga terminal Anda tetap bisa dipakai. Tunggu sampai layar HP muncul — booting butuh sekitar 30–60 detik.
4

🛑 Mematikan device (shutdown / kill)

Selalu matikan device yang sudah tidak dipakai — device yang menumpuk membuat Mac Mini berat dan test gagal. Pakai cara normal dulu; cara paksa hanya untuk device yang nge-hang.

🍏 iOS — Simulator
# cara normal — matikan satu simulator
$xcrun simctl shutdown <UDID>
# matikan semua simulator sekaligus
$xcrun simctl shutdown all
🤖 Android — Emulator
# cara normal — pakai Emulator ID dari adb devices
$adb -s <EMULATOR_ID> emu kill
# cara paksa — hanya kalau cara normal gagal
$pkill -9 -f "emulator -avd <AVD_NAME>"
⚠️ Kenapa cara paksa jadi pilihan terakhir? pkill -9 mematikan device seketika tanpa proses shutdown, sehingga data di dalam device bisa tidak tersimpan dan device berpotensi rusak saat dinyalakan lagi.

📊 Batas Maksimal Device di Mac Mini

Melebihi angka ini membuat Mac Mini kewalahan dan test gagal tanpa sebab yang jelas.

  • Simulator / Emulator: maksimal 3 device virtual (mis. 2 iOS + 1 Android, atau 2 Android + 1 iOS)
  • Real Device: 4–8 device fisik
🧯 Sebelum menjalankan pipeline Jenkins mobile, cek dulu berapa pipeline yang sedang berjalan — jangan sampai total device melebihi batas di atas.
📊 Report
📊 Melihat Report Hasil Test

Setiap kali pipeline selesai berjalan, seluruh hasilnya disimpan di build tersebut sebagai artifact. Jadi report tidak hilang — Anda bisa membukanya kapan saja, termasuk untuk build yang sudah lama.

📦 Apa itu artifact?

Artifact adalah kumpulan file hasil eksekusi yang disimpan Jenkins per build — berisi report, log, dan data mentah test. Setiap build punya artifact-nya sendiri, jadi pastikan Anda membuka build (nomor #) yang benar.
