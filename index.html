⚠️ Step 1 — WAJIB SEBELUM APAPUN
🛑 Backup File Lokal Squad

Sebelum melakukan cherry-pick dari master, backup dua file berikut yang mungkin berbeda di setiap squad:

📄 run-maestro.sh

Script runner utama. Mungkin ada kustomisasi lokal yang perlu dipertahankan.

📄 .env

Konfigurasi environment squad. Berisi Device ID, CIF, App ID, dan credentials spesifik.

✅ Cara Backup Cepat

Copy kedua file ke lokasi aman sebelum lanjut ke step berikutnya:

bash — backup
# Copy file ke lokasi backup
$ cp run-maestro.sh run-maestro.backup.sh 📋 copy
$ cp .env .env.backup 📋 copy

❌ Jangan Skip Step Ini!

Setelah cherry-pick, file lokal akan tertimpa versi master. Tanpa backup, konfigurasi squad bisa hilang.

🔄 Step 2 — Update File
Replace atau tambahkan File dari Master

5 file berikut harus diperbarui ke versi terbaru. Caranya bukan manual copy-paste, tapi menggunakan perintah Git:

Metode yang Digunakan
git cherry-pick

✅ Apa yang terjadi?
Hanya file yang dipilih yang berubah — branch squad tetap aman.
⚡ Kenapa bukan merge/pull?
Merge bisa menimpa semua file lokal squad. Cherry-pick lebih presisi.

🔄 Step 3 — Alternatif: Cherry-pick by Commit ID
Cherry-pick dengan Commit ID

Gunakan cara ini jika ingin mengambil perubahan dari commit spesifik (bukan seluruh state master).

bash — git cherry-pick
# 1. Lihat daftar commit terbaru di master untuk cari Commit ID
$ git log --oneline origin/master -15 📋 copy
# 2. Cherry-pick commit spesifik ke branch kalian
# Ganti <commit-id> dengan hash dari step 1 (contoh: a3f9c12)
$ git cherry-pick <commit-id> 📋 copy
# 3. Jika ada conflict, resolve dulu lalu:
$ git add . && git cherry-pick --continue 📋 copy
# 4. Atau batalkan cherry-pick jika ada masalah
$ git cherry-pick --abort 📋 copy

🏷️ Step 3 — Running By Tags
Include Tags & Exclude Tags

Menjalankan test berdasarkan tag — dipakai lewat config squad maupun running by tag.

includeTags whitelist

Hanya menjalankan flow yang punya tag tersebut.

excludeTags blacklist

Menjalankan semua kecuali flow yang punya tag tersebut.

Logika OR — cukup salah satu tag cocok agar flow ikut terfilter. Contoh includeTags: [AT, coba] menjalankan flow yang punya tag AT atau coba.

1 Definisikan tag di TS Script
PNS-LGT-01-TC-01.yml
appId: ${APP_ID}
name: PNS-LGT-01-TC-01
jsEngine: graaljs
tags:
- AT
- coba
- Tech-imporve

squad-config.yml
flows:
- 'login/**'
-

- Regression

- AT

🏷️ Step 5 — Git Tagging
Push with Tag in Git

Apa itu Tag?
Ibarat memberi "Stempel Versi" pada kodemu yang sudah selesai dikerjakan.

📝 Format Penamaan Tag

6.2.2-BranchIntelligent
  • 6 : Regression R6
  • 2 : Nama fitur (contoh: inbox, lifegoals)
  • 2 : Updates atau changes ke-berapa
  • BranchIntelligent : Nama Squad
bash — git tag
# Pastikan semua perubahan kode sudah di-commit (clean working directory)
# 1. Push code kamu ke branch remote terlebih dahulu
$ git push 📋 copy
# 2. Bikin Tag (Stempel) sesuai format nama squad kamu
$ git tag 6.2.2-BranchIntelligent 📋 copy
# 3. Push (Kirim) tag tersebut ke Git supaya Jenkins mulai jalan!
$ git push origin 6.2.2-BranchIntelligent 📋 copy

📊 Melihat Report Hasil Test

Setiap kali pipeline selesai berjalan, seluruh hasilnya disimpan di build tersebut sebagai artifact. Jadi report tidak hilang — Anda bisa membukanya kapan saja, termasuk untuk build yang sudah lama.

📦 Apa itu artifact?

Artifact adalah kumpulan file hasil eksekusi yang disimpan Jenkins per build — berisi report, log, dan data mentah test. Setiap build punya artifact-nya sendiri, jadi pastikan Anda membuka build (nomor #) yang benar.
